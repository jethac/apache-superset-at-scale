Technical debt over time

Every point is Superset's own measurement — oxlint run against the rules in the project's oxlint.json, by the project's own tech-debt.yml workflow. Nothing here is our estimate of the codebase, and no point is produced by the agent whose changes it scores.

The instrument, not just the metric

The project's own dashboard reports 92 violations while its configured rules produce 1,470, because the uploader omits --config oxlint.json. Where the measured rule set changes, the line breaks — the two sides are not comparable, and a continuous slope across such a change would be reporting rule removals as fixes.

Why this is the P0, and not the debt line

A fleet's output is measured in pull requests, and this is the price of one. Every change the automation files pays this bill again, so it multiplies by exactly the thing we are trying to increase: at the current median, ten open pull requests hold roughly — of compute, before a single rerun. Bringing the number down is what makes filing more work affordable, which is why it leads the roadmap rather than the violation count.

Minutes are billed job-duration summed per pull request, read from the Actions API on the repository under measurement — not from any timing the agent reports about itself.
